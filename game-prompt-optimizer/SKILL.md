# Game Prompt Optimizer

将用户的游戏想法、已有提示词、源码、README 或产品需求整理成一份完整、可复制、可执行的游戏开发提示词。

## 核心要求

- 保留用户的核心目标、技术选择和范围。
- 删除重复、模糊或互相矛盾的要求。
- 不把未经证实的推断写成事实；不声称这是原作者的真实提示词。
- 如果信息不足，使用保守假设，并标记为“建议”或“待确认”。
- 正确处理设计参考：允许采用类型通用机制和经过验证的成熟机制；禁止无设计理由地整套复制某个作品的独特规则组合、角色、世界观、关卡结构、名称或视觉表达。
- 输出完整提示词，而不是只给修改意见。
- 默认面向代码型 AI，例如 Codex、Cursor、Claude Code 或同类工具。

## 设计参考与机制借鉴

当输入提示词或设计文档提到成熟作品、竞品或“禁止照搬”时，按以下规则处理：

- “禁止照搬”不等于禁止参考，也不等于禁止直接采用成熟机制。
- 可以直接采用类型通用机制、经过多款作品验证的成熟机制，以及明显服务于本项目核心体验的设计方法。
- 如果采用某一具体作品中辨识度较高的机制，应说明采用的是哪一个设计意图、它如何服务本项目的核心体验，以及本项目在目标、规则组合、操作方式、反馈表现或使用场景上的差异。
- 不要在没有设计理由的情况下，整体复制某一作品的独特规则组合、角色设定、世界观、关卡结构、名称或视觉表达。
- 不要把“参考作品”自动改写成“必须与原作不同”；如果成熟机制适合本项目，可以保留其核心规则，但应将其放入本项目自己的玩法循环、目标和风格中。
- 转换为开发提示词时，将这类机制标记为“必须实现”“建议实现”或“明确不实现”，避免代码型 AI 把所有参考内容都当成同等优先级。

## 固定结构

生成的提示词必须按项目实际情况组织，至少包含：

1. 项目角色和目标
2. 零、阶段验收机制
3. 技术栈与工程约束
4. 游戏体验、视觉和交互要求
5. 核心玩法系统
6. 数据、网络、存档或部署要求
7. 代码质量和工程要求
8. 分阶段开发流程
9. 最终验收标准

不要为了凑章节加入与项目无关的内容。

## 提示词开头模板

输出提示词开头应明确要求：

```text
你是一名资深的软件和游戏工程师。请根据以下需求实现一个可运行、可验证、可持续迭代的项目。

项目目标：
[说明项目是什么、用户要获得什么体验、最终交付什么]

请优先保证项目能够运行和验证，再逐步增加复杂功能。除非我明确要求，不要擅自更换技术栈、扩大项目范围或引入不必要的依赖。
```

## 强制阶段验收机制

每份生成的开发提示词都必须包含以下规则：

```text
这是一个分阶段开发项目，禁止一次性实现全部功能。

每个阶段完成后，必须：

1. 运行项目。
2. 检查浏览器控制台、终端输出或测试结果。
3. 测试本阶段涉及的核心操作。
4. 修复发现的错误、崩溃、逻辑问题、布局问题和明显性能问题。
5. 再次运行项目并重复检查。
6. 汇报本阶段完成的功能、修改的文件或模块、运行方式、已测试操作、已修复问题、已知问题和验收重点。
7. 停止开发，等待我验收。
8. 只有在我明确回复“通过”“验收通过”“进入下一阶段”或意思相同的确认后，才能进入下一阶段。
9. 如果我没有通过验收，先根据反馈修复，再重新运行、检查和测试，然后重新提交验收。
10. 未经我确认，不得提前实现下一阶段。
11. 每个阶段结束时都必须保留一个可以运行的版本。
```

如果代码型 AI 无法自动打开浏览器或完成交互测试，提示词必须要求它说明已完成的检查、无法完成的检查，以及需要用户手动验证的内容。

## 阶段设计

根据项目复杂度拆分 4 至 10 个阶段。通常按以下顺序：

1. 可运行的最小项目
2. 基础交互或核心循环
3. 主要玩法系统
4. 内容、场景或数据扩展
5. 高级功能
6. 设置、存档、网络或部署
7. 性能优化和最终测试

每个阶段必须写清楚：阶段目标、具体功能、必要技术要求、用户验收重点，并要求完成后暂停等待验收。第一阶段应尽快产生可运行结果；高风险功能应放在基础版本稳定之后。

## 可验收性

禁止只写“完成游戏”“实现完整系统”等不可验证的描述。每项功能都应对应可操作的结果，例如“点击开始后进入场景”“按 WASD 可以移动”“刷新页面后设置仍然存在”。

## 最终验收

提示词结尾必须要求检查：项目启动、核心流程、主要功能、控制台或终端错误、刷新和重新开始、目标环境兼容性、部署方式和已知问题，并包含：

```text
最终测试完成后，提交最终结果给我验收。只有在我明确确认最终验收通过后，项目才算完成。
```

## 输出格式

默认输出：

1. 一句说明这是根据用户需求整理的提示词，不代表原作者的真实提示词。
2. 一份完整、可复制的提示词。
3. 简短的使用建议。

如果用户要求“只要提示词”，只输出完整提示词。不要输出冗长的分析过程。
